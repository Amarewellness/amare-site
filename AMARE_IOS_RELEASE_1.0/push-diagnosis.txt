AMARÉ iOS push — diagnosis (@ 496f63e + ios-shell prep)
=========================================================

Status: PUSH NOT READY ON iOS — ship v1 with client push DISABLED unless infra verified.

---
1. Does Capacitor push on iOS return APNs token or FCM token?
----------------------------------------------------------------
CURRENT SETUP (@capacitor/push-notifications only, no Firebase iOS SDK):

  → Returns **APNs device token** in PushNotifications "registration" event (token.value).

Evidence: PushController.tsx stores token.value as fcmTokenRef but no Firebase Messaging
bridge exists on iOS. Android uses google-services.json + FCM.

With Firebase iOS SDK + @capacitor-firebase/messaging (NOT installed today):

  → Would return **FCM registration token** (compatible with current backend).

VERDICT: Today = **APNs token**. Backend expects **FCM token**.

---
2. Do we need Firebase iOS app setup?
------------------------------------
YES — if push should work with the existing backend without code changes.

Backend (amare-notification-send.mjs) sends via firebase-admin messaging().send({ token }).
That token must be an FCM registration token for both platforms.

Action:
  - Firebase Console → same project as Android → Add iOS app
  - Bundle ID: com.amarewellness.app
  - Download GoogleService-Info.plist → Xcode project

---
3. Do we need GoogleService-Info.plist?
----------------------------------------
YES — required for Firebase iOS / FCM token bridge.

Place in: ios/App/App/GoogleService-Info.plist (after cap add ios)
Add to Xcode target membership.

DO NOT commit if repo policy treats it as secret (gitignore optional — often committed for mobile).

---
4. Do we need APNs .p8 uploaded to Firebase?
---------------------------------------------
YES — Firebase Cloud Messaging delivers to iOS via APNs.

Apple Developer → Keys → Apple Push Notifications service (APNs) → create .p8
Upload key + Key ID + Team ID to Firebase Console → Project Settings → Cloud Messaging.

Also enable Push Notifications capability in Xcode when ready.

---
5. Can current backend send to iOS tokens without backend changes?
------------------------------------------------------------------
IF AND ONLY IF the iOS app registers **FCM registration tokens** (same format as Android).

  - Raw APNs tokens: **NO** — backend has no APNs direct sender
  - FCM tokens from Firebase iOS SDK: **YES** — same amare-notification-send.mjs path

Installation API already accepts platform: "ios" (amare-notification-http.mjs).

NO backend env changes required for token format if FCM tokens are used.
Production flags (ENABLE_AMARE_PUSH=1) stay as-is on server — do not toggle in this phase.
